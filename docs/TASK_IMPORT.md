# Импорт личных задач из экспорта старой доски

Источник: `shturman_tasks_export_*.json` (кнопка «Экспорт задач в JSON» старой доски). Назначение —
существующая коллекция `tasks` «Доски проектов». Код: `server/taskImport.js`.

## Как выполнить на Railway (без shell и без ручной правки `/data/shturman.json`)

1. Резервная копия Volume (`node scripts/snapshot_data.js` или снимок Railway).
2. Дашборд → «Интеграции» → «Импорт личных задач из экспорта» → выбрать файл → «Проверить (dry-run)».
   Ничего не записывается; показываются количество задач и подзадач, новые, уже существующие,
   конфликты, соответствие категорий и поля, переносимые с потерями.
3. «Импортировать N задач». Сервер заново проверяет план; если доска или файл изменились после
   проверки — отказ (409) и повторная проверка. Запись — одна атомарная операция.
4. Откат: в списке импортов «Откатить» — сначала показывает, что будет удалено; удаляются только
   задачи этого импорта, не изменённые после него.

API (сессия дашборда; запись — с `X-CSRF-Token`): `POST /api/admin/task-import/analyze`,
`POST /api/admin/task-import/apply` (`plan_hash` из dry-run), `GET /api/admin/task-import`,
`POST /api/admin/task-import/:id/rollback` (`dry_run`, `force`).

Локально (сервер остановлен): `node scripts/import_artifact_tasks.js <file> [--write]`,
`--rollback <manifest> [--write] [--force]`.

## Что переносится

| Поле экспорта | На доске | Примечание |
|---|---|---|
| `id` | `id` задачи | защита от дублей: повторный импорт пропускает существующие id |
| `title`, `direction`, `responsible`, `from`, `due` | как есть | срок не переформатируется |
| `quadrant` | категория | `inbox/do/plan/delegate/drop` 1:1; неизвестная → «Распредели», исходное значение в `import.original_quadrant` |
| `done` | `done` | выполненные остаются выполненными |
| `subtasks[]` | `subtasks[]` | копируются целиком, со своими id и полями |
| `created_at` | `createdAt` (+ `importedCreatedAt`, дата строки) | дата не заменяется сегодняшней |
| `updated_at` | `importedUpdatedAt` | служебная дата изменения доски — момент импорта |
| `telegramNotified`, `calendarSynced`, `source` | как есть | при импорте ничего не отправляется |
| прочие поля | `import.extra` | сохраняются, но не отображаются |

Не создаются: приоритет, описание, связи с инженерными проектами. Telegram и ИИ не вызываются.
Импортированные активные задачи дальше живут как обычные задачи доски — они попадут, например, в
утреннюю сводку, как и любые другие активные задачи.

## Конфликты

- `id_used_by_existing_task` — id уже занят задачей, созданной не этим импортом: она не меняется,
  запись пропускается, остальные импортируются.
- `duplicate_id_in_file`, `missing_id`, `missing_title`, `not_an_object` — файл повреждён: импорт
  целиком запрещён.
- Совпадение названия с существующей задачей — предупреждение (задача импортируется, проверьте вручную).
