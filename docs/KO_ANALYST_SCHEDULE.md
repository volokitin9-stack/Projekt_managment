# Ежедневный анализ чата КО — 16:00 Екатеринбург

Статус: **подготовлено, расписание НЕ создано и НЕ включено.** Включать только после успешного
ручного теста (шаг 3).

## Как это работает

```text
Claude Code Scheduled Task (подписка, облако, среда «Сборка планов»)
  └─ новая облачная сессия: клон репозитория, .claude/agents/ загружаются при старте
       └─ субагент shturman-ko-analyst (с хуком ko-analyst-guard.js)
            ├─ GET  /api/agent/ko/cursor, /messages, /projects, /proposals   (Network Secret)
            ├─ POST /api/agent/ko/proposals   → очередь «Предложения агента КО»
            └─ PUT  /api/agent/ko/cursor      → только после успешной отправки
```

Платные API не используются: анализ делает сама сессия Claude Code в рамках подписки. На Railway
нет вызовов LLM (`TELEGRAM_ENGINEERING_AI_ENABLED=false`). В чат КО ничего не отправляется:
ограничения в трёх местах — хук субагента (запрет `api.telegram.org`), отсутствие у ключа
`KO_ANALYST_API_KEY` любых прав, кроме чтения архива, предложений и курсора, и серверный запрет
исходящих вызовов в чат КО (`server/telegram/botApi.js`).

## Что проверено

| Вопрос | Результат |
|---|---|
| Облачная сессия загружает агента из `.claude/agents/` | Да: в этой облачной сессии `shturman-ko-analyst` появился среди типов агентов из файла репозитория и выполнил предварительный анализ |
| Network Secret работает в облаке | Да: `GET /api/agent/ko/projects` → 200 (132 проекта), подстановка ключа прокси |
| Субагент ходит через тот же прокси | Да: предварительный анализ получил сообщения и проекты |
| Какую ветку клонирует Scheduled Task | **Не подтверждено.** Ветка по умолчанию в GitHub — `main`, в ней нет агента и KO-API. См. шаг 1 |

## Внедрение

1. **Ветка.** Агент и курсор должны быть в той ветке, которую клонирует облачная сессия. Варианты:
   сделать `claude/railway-deployment` веткой по умолчанию в GitHub (Settings → Branches) или влить
   её в `main`. Без этого задача не найдёт агента и, по инструкции ниже, остановится без анализа.
2. **Railway.** Развернуть ветку с `PUT/GET /api/agent/ko/cursor` (этот релиз). До этого курсор
   недоступен — задача остановится на первом шаге.
3. **Ручной тест** — новая облачная сессия в среде «Сборка планов» (или одноразовый запуск задачи
   без расписания) с промптом ниже. Ожидание: отчёт агента, курсор = `last_seq`, предложения (если
   есть) в «Предложения агента КО», ничего не применено.
4. **Включение.** Только после шага 3: Scheduled Task, «новая сессия на каждый запуск», среда
   «Сборка планов», cron `0 11 * * *` (UTC = 16:00 Asia/Yekaterinburg, UTC+5, без перехода на
   летнее время), промпт ниже.

## Промпт задачи

```text
Ежедневный анализ чата КО для «Доски проектов».
Делегируй работу субагенту shturman-ko-analyst (Agent, subagent_type: shturman-ko-analyst) с заданием:
«Ежедневный режим. Выполни раздел "Ежедневный режим" своих инструкций полностью: курсор → новые
сообщения → анализ → POST предложений → PUT курсора только после успешной отправки → краткий отчёт».
Если субагент shturman-ko-analyst недоступен в этой сессии — НЕ выполняй анализ сам и ничего не
отправляй на сервер: сообщи «агент не загружен» и заверши работу.
Запрещено: сообщения в Telegram, изменение проектов, git push, платные LLM API.
В конце выведи отчёт субагента без текстов сообщений и персональных данных.
```

## Откат

Выключить или удалить Scheduled Task. Курсор и поданные предложения остаются; отклонить лишнее
можно в «Предложения агента КО». Сдвинуть курсор назад API не позволяет (защита от повторной
обработки) — при необходимости повторного анализа это делается отдельной ручной операцией.
